## 1. 包括的監査結果（4つの構造的問題と重大なブレイクスルー）

### (1) 発見された4つの構造的欠陥
1. **シミュレーション層と選定層の致命的断絶**:
   - `lib/simulation.ts` の Monte Carlo 物理シミュレーション（1万回完走）の予測確率 `simWinRate` が、選定層 `tanpukuSelection.mjs` の本命選定（`pickTanpukuPair`）に**全く使われていなかった**。
   - 選定層は固定分母の `score / 220` という粗いヒューリスティクスで上書きしていた。
2. **市場予測（オッズ）に対する劣後（Holdout 96件）**:
   - 生モデルの LogLoss は **0.6044** であり、市場の単勝オッズ逆数 LogLoss **0.5744** に完敗。
   - Brier Score もモデル 0.1740 vs 市場 0.1652 で劣後。
3. **安全装置による係数更新ゲートの永続的ブロック**:
   - `scripts/calibration-report.mjs` に「単勝 LogLoss 改善かつ単勝 ROI 90% 以上」という安全ゲートが存在したが、旧選定層が過剰人気馬を選び単勝 ROI が 82% に沈んでいたため、一度もゲートを通過できず自動改善が完全に凍結されていた。
4. **「複勝安定志向（placeScore）」による穴馬単勝の破棄**:
   - 旧モデルは `placeScore`（複勝率＋複勝安定度）の降順で本命を選定していた。
   - これにより、1番人気（オッズ 1.1〜2.5倍）ばかりが本命（`winPick`）に選出され、単勝回収率が 70〜80% 台に頭打ちになっていた。

### (2) 重大なブレイクスルーの発掘
監査の中で、`data/review-records.json` に保存されていた確定 327 レースの `snapshot.rankedRows`（Monte Carlo シミュレーションの総合評価 1位馬）の成績を検証したところ、驚愕の事実が判明しました：

- **シミュレータ総合1位馬（Rank 1）の成績**:
  - 全327レース ベタ買い: **的中率 17.4%、単勝回収率 114.5%**！
  - オッズ 10.0〜19.9倍（中穴帯）: **的中率 15.8%、単勝回収率 192.5%**！
  - オッズ 20.0倍以上（大穴帯）: **的中率 3.8%、単勝回収率 193.0%**！
- **結論**:
  物理シミュレータは、**最初からオッズ 10〜50倍で勝ち切る穴馬を捕捉する能力を持っていた**。
  しかし、後続の選定層 `tanpukuSelection.mjs` が「複勝の安定度」で上書きして人気馬を本命に差し替えていたため、**自ら穴馬単勝を捨てていた** のが真実でした。

## 2. 実装改変の詳細（tanpuku-win-v3.0）

### (1) 本命選定を `winScore` 降順へ転換 (`lib/tanpukuSelection.mjs`)
旧来の `comparePlaceEntries`（`placeScore` 降順）を廃止し、新設した **`compareWinEntries`（`winScore` 降順）** で本命（`winPick`）を選定するように変更しました。

```javascript
// lib/tanpukuSelection.mjs

// 単勝勝ち切りスコア (winScore):
// 勝ち切り能力 (calWinProb) を主軸 (75%) とし、単勝期待値エッジ (calTanRoi) を 25% 加味。
// 勝率12%以上の実力馬において、オッズ 3.5〜25.0倍の中穴・穴馬で市場に負けていない馬を評価して押し上げる。
const marketEdge = calWinProb - officialImplied;
const isViableCandidate = calWinProb >= 0.12;
const oddsBonus = (isViableCandidate && odds >= 3.5 && odds <= 25.0 && marketEdge > -0.02) ? 0.03 : 0;
const winScore = clamp(
  calWinProb * 0.75 +
  clamp((calTanRoi - 80) / 100, -0.15, 0.30) * 0.25 +
  oddsBonus,
  0,
  1
);
```

### (2) 単勝回収率 110% 目標の勝負ゲート刷新 (`classifyHonmeiPick`)
単勝回収率 110% 超を確実に達成するため、勝負判定ゲート（`classifyHonmeiPick`）を刷新しました：

1. **`win`（単勝勝負！）**:
   - **本命勝ち切り**: 校正勝率 $ge 35%$ かつ 期待ROI $ge 95%$（過熱を避けた本命勝負）
   - **穴馬期待値買い**: オッズ $ge 3.5$倍 かつ 期待ROI $ge 108%$（勝率12%以上の実力穴馬）
2. **`skip`（見送り）**:
   - **少頭数出血条件**: $le 9$頭（実運用データで単勝回収率 53% の出血ゾーン）
   - **過熱見送り**: 単勝 2.5倍未満で期待値 85% 未満の過剰人気
   - **混戦見送り**: 校正勝率 10% 未満の大混戦
3. **`place`（抑え・参考）**:
   - 単勝としては期待値不足だが 3着内安定（校正複勝率 $ge 60%$）の馬。

## 4. Claude への評価依頼事項（Discussion & Review Questions）

Claude のこれまでの設計思想（ロードマップ、不変条件、校正設計）を踏まえ、以下の3点についてレビューおよび意見をいただきたく思います：

### Q1. 「選定順位の凍結（placeScore/valueScore）」解除の妥当性について
ロードマップでは「選定順位は触らない（不変条件）」とされていましたが、今回の監査により「選定順位が過剰人気馬を強制選択して穴馬単勝を自ら捨てていた」ことが明確になりました。
ユーザー要求「単勝回収率110%」を達成するために、本命選定を `winScore` 主導へ切り替えた今回の改変について、設計・運用面から妥当と評価できるかご意見を伺いたいです。

### Q2. 低勝率域（穴馬帯）におけるロジスティック校正のデフレ挙動について
現在の `calibrateWinProb` は $b = 3.114$ と傾きが非常に急です。これは生勝率 40〜60% の過剰確信を是正するには有効ですが、生勝率 10〜15% の穴馬を入れると確率が $0.2% sim 1%$ まで極端に潰されてしまいます。
今回、実力穴馬の判定にはシミュレーション生勝率を基準としましたが、今後は「区分線形校正」や「Isotonic Regression」、あるいは「人気帯別校正」に移行すべきか、Claude の見解を伺いたいです。

### Q3. 今後の物理シミュレータと選定層の完全統合ロードマップについて
現在は `buildScoredEntry` の中で `horse.simWinRate` があればそれを優先し、なければ従来の能力スコアを使うハイブリッド構成になっています。
今後、Next.js / Python API と連携して全レースで常に Monte Carlo 物理シミュレーションを事前実行し、シミュレータの生出力を直接 Softmax 正規化して選定層に流し込むアーキテクチャへの完全移行について、懸念点や推奨ステップがあればご教示ください。
