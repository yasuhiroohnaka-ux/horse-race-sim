## 無料を目指す最小構成と検収条件

サイト Worker + Workers Assets + 非公開 R2 Standard が機能維持の最小構成。D1、KV、有料画像サービス、独自ドメイン追加は不要。dispatcher は定時性改善用の追加 Worker であり、初期のサイト検証時は既存 GitHub schedule を継続できる。

Workers Free は 100,000 requests/日、CPU 10 ms/invocation。静的資産の配信は無料。R2 Standard は月10 GB-month、Class A 100万、Class B 1000万の無料枠。無料枠は請求上限ではない。Workers Paid への変更は未承認。

最大の実行上の未確認点は Workers Free の CPU/メモリ制約。スナップショット API は約9 MBのJSONLと約20 MBのreviewデータを解析し、R2の保存オブジェクトも列挙するため、無料運用可否は実環境計測前に確約しない。重いAPIが無料CPU枠に収まらなければ、公開データの集計をActions/ビルドへ移すなどの最適化を先に検討する。有料化を自動で行わない。

7資産の個別サイズはすべて25 MiB以下。最大 `data/review-records.json` は19,758,711 bytes（18.84 MiB）。全体で41,131,701 bytes。今後の履歴増加にも注意が必要。
